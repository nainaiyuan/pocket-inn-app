## 一、底层引擎现状（已落地 ✅）

**运行时三层**（全部配置驱动，不配置 = 老行为完全不变）：

- `PetWorld` / `PetScene` / `PetGroupRuntime`（互动组运行时已抽成纯 Dart，可单测）
- 互动组 = **坑(slots) × 剧本(steps)**，每步每坑 = 动作 + 移动
- 移动类型：stay / dir(8方向) / spot(定点) / approach(靠近搭档) / leave(离开搭档)
- 控制权体系：auto / user / interaction / response
- 距离自动触发、提起暂停/放下续播、散场模式

**今日新增 4 行为（commit 2a0ebd5，13 单测全过）：**

| 能力 | 配置字段 | 行为 |
|------|---------|------|
| ① 编队移动 | `formationLeaderId`（步骤级） | 带头坑走，stay 坑保持相对偏移跟随；带头被抓住 → 退化为普通步 |
| ② 待机行为 | `idleActionId`（坑级） | 坑没任务且 stay → 循环播该动作（不再干站着） |
| ③ 提起反应 | `heldReactionActionId`（坑级） | 成员被提起 → 其他坑播反应动作（去重，放下后可再触发） |
| ④ 摆放行为 | `placedActionId`（坑级） | 坑从 held→放下时自己播该动作 |

JSON 用短键（'ia'/'hr'/'pa'/'fl'），老数据无新字段 → 默认 null，**零迁移**。

## 二、产品方向（昨天 PPT 方案摘要，2026-08-15 01:12 备份）

长期定位：**「让用户自己创建 OC 世界、角色、关系、剧情和互动玩法，再由 AI 让角色真正演出来」**

= AI角色 + 桌宠 + 互动文游 + OC世界编辑器 + 陪伴系统

**5 种运行模式（同一套底层）：**
1. 桌宠模式（当前）—— 桌面走动/待机/被拎/被扔/聊天/AI控制
2. 全屏互动文游 —— 立绘/场景、多角色站位、说话/移动/表情/选项/自由输入
3. 小游戏模式 —— 点击/拖动/收集/条件触发/探索
4. AI 陪伴模式 —— 定时提醒/睡前陪伴/到点主动弹卡片
5. 编辑/创作模式 —— 角色/立绘/表情/动作/场景/剧情/分支/事件

**核心概念：AI 是"导演"，不是聊天框。**
AI 输出演出指令（`character.say / setExpression / moveTo / playAction / face / enter / exit / choice.show / scene.change`），引擎执行，AI 不碰 Flutter UI。
AI 只表达语义（`expression=smile`），资源映射系统决定具体图片。

**站位统一坐标**：X=0~1、Y=0~1、Scale、Layer、Facing，不写死 left/center/right，用户可拖。

## 三、用户 UI 构想（原话整理）

> 「管家页面已经有单角色和多角色的配置入口，那么我们就直接在下面再添加，
> 比如聊天页立绘、文游、各种东西的配置入口，然后底层的东西都是复用的。
> 我们现在只需要打磨管家这个模块，到底怎么方便用户去设置不同的东西，
> 然后其余的页面就只是显示而已。
> 设置页面也要有一个地方可以实时的显示到底怎么配的。
> 立绘交互的页面就直接是交互，不直接配置。」

**核心诉求拆解：**
1. **管家 = 唯一配置中心**：单角色 ✅已有、多角色 ✅已有，下面继续加：立绘、文游、小屋等入口
2. **其余页面纯展示/纯交互**：立绘聊天页直接交互，不带任何配置 UI
3. **实时预览**：设置时能实时看到"配出来是什么样"（预览框 = 真实小人，不是圆圈）
4. **底层全复用**：不按模式各写一套
