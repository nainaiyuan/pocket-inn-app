# 动作编辑页：预览与播放速度 — 问 GPT 方案材料

> 日期：2026-08-15
> 背景：单角色配置中心（桌宠 App）里"动作"模块的 UX 问题。用户（非技术）看不懂现在的预览和速度表达，需要 GPT 给设计方案。
> 附：配置中心全貌见 `docs/管家配置中心_现状与规划_问GPT.md`

## 一、背景

桌宠 App 有"单角色配置中心"，用户给角色配置：
- **动作**（帧动画：一组图片按顺序播放 = 走路/挥手/吃东西）
- **行为**（动作的组合方案：日常待机 = 随机播走路/挥手/发呆）
- **状态 / 区域 / 对象 / 触发**（持续状态、屏幕上的地方、静态物、什么时候做什么）

本材料聚焦**动作编辑页**。

## 二、动作编辑页当前实现（代码现状）

文件：`lib/pages/character_config/action_editor_page.dart`

**用户编辑一个动作时的界面**：
1. **动作名称**（文本框）
2. **归类**（下拉选择 + 可新增，如 移动/互动/待机/表情）
3. **图片帧区**：
   - 「添加帧」按钮 → 从相册多选图片，显示为缩略图列表
   - 每张缩略图右侧有 上移 / 下移 / 删除 按钮
   - 长按缩略图弹出「移到最前 / 移到最后」
   - 「▶ 预览播放」按钮：**只是按当前速度循环高亮缩略图边框**（第 1 张亮一下→第 2 张亮一下…），再点停止
4. **播放速度**：滑块 1~30，"每秒 N 张"（如"每秒 8 张"）
5. **循环方式**：一次 / 循环

## 三、用户困惑（原话转述）

1. **"编辑动作里面每一步根本没有预览"** —— 用户以为的预览是：**在真实设备框里看到小人/角色怎么动**（像桌宠页那样有个角色展示框，帧图在里面真实播放）。现在的"预览播放"只是缩略图高亮循环，用户觉得这不算预览，看不到真实效果。
2. **"播放速度/图片切换快慢，用户根本看不懂，说什么每秒十张"** —— 用户不关心"每秒几张"，只关心**"我扔了这么多图片，这一组一共多少秒播完？"**。需要的是**总时长**概念（帧数 ÷ 每秒张数 = 总秒数），而不是帧率术语。

## 四、期望效果（用户想要的）

1. **编辑页内嵌真实预览框**：模拟桌宠页的角色展示框——有背景、有角色比例，帧图在里面按当前速度真实循环播放，调整速度立刻看到变化。
2. **速度表达改成用户能懂的**：滑块直接显示"**这一组图共 X 秒播完**"（随帧数实时换算），或者两种表达同时给（"每秒 N 张" + "共 X 秒"）。
3. 用户希望所有编辑页面都统一这种"所见即所得"的思路。

## 五、请 GPT 回答的问题

1. **预览框怎么设计**：尺寸多大合适（平板为主）？帧图可能是透明 PNG、也可能是不规则尺寸，怎么适配（contain？居中？）？背景用什么（格子底/纯色/模拟桌宠场景）？循环播放时帧与帧之间要不要过渡（直接切 vs 淡入）？
2. **速度表达**：滑块怎么改最易懂？推荐"总时长"为主、"每秒张数"为辅的双显示？总时长 = 帧数 ÷ fps 的换算要不要在滑块 label 实时显示？帧数为 0 时怎么显示？
3. **预览与真实桌宠的一致性**：编辑页预览框和桌宠页真实运行时的显示（角色框比例、帧图大小）如何保持一致，避免"编辑时看着好、跑起来不一样"？
4. **行为页是否也要预览**：行为 = 多个动作按顺序/随机播放，编辑行为时要不要也内嵌一个预览（按条目的等待秒数真实播放动作序列）？
5. **性能**：帧图几十张、每张几 MB 时，编辑页内嵌预览会不会卡？需要缩略图缓存策略吗？
6. **其他**：预览播放时如果用户正在调速度滑块，要不要实时生效（边拖边看）？
