### 结构化需求

**A. 全屏场景（文游 + 小屋统一）**
1. 场景表：一张底图 + 角色摆位 + 热点列表；2 楼 = 多个场景切换
2. 底图/家具/道具素材：用户上传（待确认：是否先做占位素材）

**B. 热点统一模型（一个模型四种形态）**
- 热点 = { 形态 + 位置/区域 + 绑定内容(动作组/卡片) + 触发方式 }
- point：文游的"点"（可挂角色身上跟角色动 / 固定屏幕），点击触发
- area：活动区域（矩形，不占满屏），小人进入触发
- furniture：家具（床/桌/椅素材绑一起，固定位），走到附近点击/自动触发
- item：道具，用户拖到小人身上触发（投喂）
- 绑定内容：动作组（现有 activity/互动组）+ 卡片

**C. 卡片系统（文游卡）**
- 纯文字卡 / 选项卡（多个按钮如"推开他/抱住他/转头离开"）
- 点选项 → 触发下一组动作（选项即分支）
- 卡片内容用户可配置

**D. 互动链（轻量节点）**
- 热点点击 → 动作组演出 → 弹卡片 → 用户点选项 → 下一组动作 → 下一张卡片…
- 复用现有互动组剧本机制，新增"步骤之间插入等待卡片"暂停点
- 核心原则（用户早期确认过）：节点等用户操作时，操作完成前不自动跳过

**E. AI 立绘聊天（= AI 聊天换输出端）**
- 全屏场景 + 立绘 + AI 自主触发动作/表情（演出指令 character.say/setExpression/playAction/moveTo/enter/exit/choice.show）
- 聊天框 = 卡片框，用户打字回复
- 同一套对话引擎，输出端从"桌宠小人+气泡"换成"全屏立绘+卡片"

**F. 随时打断** = 现有控制权系统（user 一抓全停）
